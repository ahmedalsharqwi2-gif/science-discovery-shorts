# إنتاج الصور المتحركة المعتمد

قالب عمودي 1080×1920، 30fps، مستخرج من أسلوب عينة دنكرك: صور سينمائية كاملة الشاشة، حركة كاميرا هادئة، طبقات أمامية مستقلة، انتقالات قصيرة، خرائط ومحددات مؤلفة، وخط Noto Sans Arabic مع تشكيل واتجاه عربي صحيحين.

## ما يعمل الآن

- حلقة تحدد الصوت والصور والتوقيت في episode.json؛ لا تعتمد على موضوع دنكرك في المحرك.
- ثلاثة ملفات أسلوب: history وscience وhorror. تختلف الألوان والإيقاع والهوية، ويمكن تأليف طبقات توضيحية مناسبة لكل موضوع.
- الحفاظ على التسجيل المعتمد كاملًا دون تغيير سرعته أو طبقته أو استبدال الصوت.
- رفض نقص الصور أو تبدل بصمتها أو عدم اكتمال التوقيت أو تجاوز النص للمساحة الآمنة.
- فحص MP4 كاملاً، مطابقة مدة التسجيل، مقارنة الصوت بعد الترميز ومقارنة إطارات المشاهد بالتصميم المؤلف.
- ربط اختياري بالـ assemble_video الحالي عبر PHOTO_MOTION_MANIFEST، مع اشتراط تطابق نص الحلقة والصوت مع ملف المراجعة.

هذه فحوص تقنية؛ لا تستطيع تلقائيًا ضمان جودة الأداء الصوتي أو الإخراج أو صحة كل معلومة. اعتماد حقول review يسجل اسم من راجع المادة ولا يمثل تقييمًا ذكيًا تلقائيًا. تظل مشاهدة وسماع النسخة الكاملة ضرورية، خصوصًا أول حلقة من كل قالب.

## التشغيل من GitHub

Actions → **Approved Photo Motion** → **Run workflow**، ثم مسار episode.json داخل المستودع. في مستودع التاريخ، حلقة Dunkirk مرفقة كنسخة طويلة للمراجعة؛ مدتها 77.6 ثانية و15 لقطة، والتسجيل من الفيديو الأصلي المرفوع. المصادر والتفاصيل داخل ملف الحلقة.

التشغيل يرفع **approved-photo-motion-video**: الفيديو، تقرير الفحص ولقطات المشاهد. لا ينشر على منصات التواصل. الحلقات الجديدة توضع في مجلد مستقل، ومعها أصولها، ثم تمرر مسار ملفها لنفس التشغيل.

```bash
pip install -r photo_motion/requirements.txt
python -m unittest discover -s photo_motion/tests -v
python -m photo_motion.engine --manifest photo_motion/episodes/dunkirk/episode.json --validate-only
python -m photo_motion.engine --manifest photo_motion/episodes/dunkirk/episode.json --output output/final_video_full.mp4
```

يتطلب FFmpeg وPillow مع libraqm. GitHub Actions يثبتهما تلقائيًا. الخطوط مرفقة وترخيصها في assets/Noto-Fonts-Copyright.txt.

## إعداد حلقة جديدة

1. اكتب النص النهائي وراجع معلوماته، وسجل مصادر التاريخ/العلوم.
2. أنتج الصوت أو قدم التسجيل ثم اسمعه واعتمده. حدّد مصدره الحقيقي في audio.provenance. معرفة نفس voice_id من MP4 وحده غير ممكنة.
3. جهز الصور والطبقات المناسبة للنص. الصور المولدة توسم بأنها توضيحية؛ الخرائط تبنى من بيانات جغرافية موثوقة.
4. ألّف مشاهد تغطي التسجيل كاملًا: start/end وbackground وعنوان مختصر وسبب ارتباط الصورة بالكلام. الحركة camera_start/end بصيغة [zoom,pan_x,pan_y]؛ الطبقات start/end بصيغة [x,y,height].
5. ضع captions بتوقيت الكلام الفعلي بعد المحاذاة والمراجعة، وحدّث asset_sha256. انقل review بصدق إلى الإصدار الجديد بعد مراجعته؛ لا تنسخ الاعتماد تلقائيًا.
6. شغّل الفحص ثم الرندر وشاهد النتيجة الكاملة.

## الربط بالإنتاج السابق

حدد PHOTO_MOTION_MANIFEST لمسار الحلقة المعتمدة. العلوم تستقبل الصوت والنص من الدالة الحالية. التاريخ والرعب يقرآن current_episode.json. عند أي اختلاف في النص أو الملف الصوتي يُرفض الرندر ولا ينتقل تلقائيًا إلى قالب آخر. عند عدم ضبط المتغير يبقى المسار السابق كما هو. إعداد التشغيل الجديد لا يعيد تفعيل جداول الإنتاج أو النشر السابقة.

لم نربط المحرك ببديل صوتي أقل جودة. إنتاج نصوص جديدة بنفس صوت المرجع ما زال يتطلب تحديد خدمة الصوت والموديل وvoice_id أو اعتماد صوت جديد بعد سماعه. الصور الجديدة كذلك تحتاج مصدرًا حقيقيًا؛ الصور المرفقة أُنشئت في جلسة ChatGPT، ولا توجد خدمة مجانية وهمية لتوليدها داخل GitHub. لا يستخدم المسار مفاتيح API أو اشتراكات مدفوعة.

اختيار هذا المحرك يحافظ على طريقة تركيب الصور والخطوط في العينة المعتمدة. مكتبات video-toolkit تظل متاحة للمشاهد التي تحتاج رسومًا أو مؤثرات أخرى؛ تثبيت مكتبة لا يجعل كل المشاهد تستعملها تلقائيًا.
