# Review runbook

Use Node 22, Python 3.11, FFmpeg/ffprobe, then `npm ci`, `python -m venv .venv`, `.venv/bin/pip install -r requirements.txt`, `PYTHON=.venv/bin/python make review`. Provider bindings: GEMINI_API_KEY or separate GEMINI_TEXT_API_KEY / GEMINI_TTS_API_KEY; only environment references, never paste values in code or reports. Image generation uses GEMINI_API_KEY (or text binding) for stickman realistic backgrounds. Preserve original logo at public/brand/logo.png and configure config/channel.json; no substitute artwork.

`make test` runs policy/evidence tests and TypeScript checks. `npm run preview` opens the scene template preview. `out/<run>/report.json` records successful stages and the first failing stage. Actual review.mp4, contact-sheet.jpg (one frame per three seconds), props, script, sources, attributions and QA are produced only after the relevant stages pass. No audio/video fallback fabricates successful speech. The aligner intentionally fails if ASR and source words cannot be defensibly matched; pronunciation/ASR differences need a measured forced-alignment improvement rather than estimated timing.

One daily.yml workflow runs checks and a review-only attempt on same-repository PRs, manual review dispatch and 14:00/15:00 UTC cron. The exact Africa/Cairo 17:00 guard handles DST. GitHub schedule delivery can be delayed: if it misses the exact minute the run skips; durable catch-up is not yet implemented. Concurrency serializes runs; review-media stores reports/media/reservations without force pushing; existing media is retained. A PR branch never enables a new cron on main until merged. Existing external scheduler bindings were not changed; audit them before any eventual cutover to avoid simultaneous legacy production.

Publication is deliberately unavailable: config/release.json has publish_enabled=false, publish mode errors even if config is edited, and /api/youtube/upload returns 403 after authentication. To enable later, owner review must approve the MP4 and an explicit publishing implementation/security review in a separate PR; changing a Boolean alone does not silently activate upload. Never merge this rebuild as production-ready until six complete review films, all required QA and exact original logos have been accepted.

The rebuilt Nafhamha service changes /api/render to a review runner and removes legacy OAuth/media/voice routes. Dashboard integration compatibility is NOT established; do not deploy it over the existing service without adapting and testing callers. Docker build not assumed tested. Auth requires API_TOKEN at least 32 characters; health requires no token. Render lock excludes parallel jobs; no error dumps provider bodies, keys or headers.
